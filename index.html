The Shift

Before and After AI

I've built software both ways. For me, most of the difference comes down to how the team is put together.

Pre-AI Era

The Old Workflow

  • Five specialists needed: backend, frontend, DevOps, QA, and technical writer
  • Full salary, pension contributions, and benefits for each of five people
  • Annual leave and sick days push project dates back, often at short notice
  • Knowledge transfer takes time whenever someone joins, leaves, or changes role
  • The frontend waits for the backend, and QA waits for both
  • Timezone gaps and calendar clashes keep people waiting on each other every day
  • Finding an answer means a slow hunt through Google, Stack Overflow, and the docs
  • Manual code reviews lose days to comment threads and rework
  • Knowledge lives in people's heads and goes when they do
VS
Post-AI Era

The New Workflow

  • One AI-fluent engineer leads a team of AI agents that cover all five roles
  • Agents cost LLM tokens instead of five salaries, pensions, and benefits
  • Leave and sick days don't apply to agents, so they're available 24/7
  • Each agent session starts from persistent memory, which replaces knowledge transfer
  • Backend, frontend, and QA tasks run at the same time
  • Work starts as soon as the project needs it, whatever the timezone
  • Getting answers from the codebase itself is faster and more accurate than a web search
  • An agent reviews every commit straight away and refactors where needed
  • Project knowledge stays in agent memory and skills
Personal Evolution

Six Phases of Using AI

I went through these phases in order. Each one changed the way I worked and what I could take on.

01
Phase One 💬 AI as a Smarter Search Engine

Google used to be my default. Then I started asking AI to explain concepts and documentation, and to show me where my understanding was off. Instead of scanning ten Stack Overflow threads, I got answers faster by asking follow-up questions about my exact problem.

⚡ 2× faster information retrieval
02
Phase Two 🔍 AI-Assisted Code Review & Generation

AI began writing code snippets and reviewing my PRs. The implementation was still manual. I'd copy the code, adapt it, test it, and commit it myself. But the quality bar rose. The AI caught bugs before they shipped and suggested patterns I hadn't considered, even at the end of a long review.

⚡ Better code quality, faster reviews
03
Phase Three 📄 Context-Driven Code Generation

Once I learned to give AI real project context (architecture docs, screenshots, API specs), the code it wrote looked like it belonged in my codebase. It could scaffold entire modules from a project brief, and its solutions took the rest of the system into account.

⚡ Complete features built from a brief
04
Phase Four 🤖 The Autonomous AI Agent

This was the biggest jump for me. The agent understands the whole project and can plan, implement, test, and fix things on its own. I describe the result I want and let it work out how to get there. When it changes code or makes an architecture decision, it can explain why.

⚡ From pair programming to delegating tasks
05
Phase Five 👥 Running a Team of AI Agents

Next came a virtual department, with me as the team lead. Agents for backend, frontend, DevOps, QA, and documentation all work on the same project in parallel and carry on through nights and holidays. They coordinate through shared memory and follow the coding standards I wrote into their skills. As they push their work to GitHub, they keep the README files up to date.

⚡ One person = a full engineering team
06
Phase Six ⚙️ Automating Everything Repetitive

AI does a lot more for me than write code. It sorts my email, summarises and schedules meetings, manages folders, processes spreadsheets, and builds a presentation when I ask for one. I hand off the repetitive work that would otherwise take me hours.

⚡ Automation across work and everyday life

Cost Control

How I Cut Token Costs

AI is part of the job now. Using it without wasting tokens is harder, and I think it matters more, because the bill climbs quickly if nobody is watching.

🧩
Build Reusable Agent Skills

I put the project's architecture and coding standards into skills and memory that every agent inherits. That way I don't have to repeat myself.

✂️
Keep the Context Small

The agent only gets what the current task needs. Loading the whole codebase just burns tokens when a short excerpt would do.

🔁
Persistent Memory Across Sessions

Agents that remember past decisions and the project structure don't spend tokens on a fresh tour of the codebase each session. As their memory grows, they get to know the project better.

🎯
Precision Prompting

A vague prompt sends the agent off exploring, and the detours add up. When I spell out the task and what a good result looks like, the first attempt is right more often.

📋
Task Scoping & Batching

I group related changes into one agent session. Every new session costs tokens to set up before the agent does any real work, and I'd rather pay that once per batch.

📊
Monitor & Audit Token Usage

Before a long autonomous run, I set a token budget for it. I also track usage per project and per agent, which shows me early on whether spending is heading towards the monthly limit.
